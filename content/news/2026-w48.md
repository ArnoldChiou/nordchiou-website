本週有兩個趨勢。第一，大廠持續把 AI 代理放進企業每天在用的工具：微軟把 Copilot 全面帶進 Office，並和 Salesforce 合作把客戶資料接進 Copilot；Google 則讓代理在 API 中依需求挑選工具。第二，導入規模變大後，治理變得更重要。BMW 管理數百個代理的做法、Standard Bank 自動化 AI 風險評估，以及本週接連發生的第三方供應商資安事件，都說明了一件事：AI 與委外服務接進核心流程之前，要先想清楚權限、證據留存與供應商風險。對台灣企業來說，現在適合從既有的辦公工具與文件流程開始導入，同時把治理機制一起建立。

## 1. 微軟 Office in Copilot 全面上線，Autopilot 開放搶先體驗

**模型與產品**｜來源：[iThome](https://www.ithome.com.tw/news/180679)｜2026-11-20

iThome 報導，微軟本週在 Ignite 大會上宣布，Office in Copilot 已正式部署給所有用戶。微軟同時發表多項給商務環境用的代理服務，包括開放搶先體驗的自主代理 Autopilot、給商務用戶的 Workspaces，以及 Dynamics 365 in Copilot。

> **對企業的意義**：已經使用 Microsoft 365 的企業，可以先盤點哪些文件、簡報與報表作業適合交給 Copilot，再挑一個部門試用。自主代理目前只開放搶先體驗，建議先觀察權限控管與稽核功能是否成熟，再考慮讓它處理正式流程。

## 2. AWS 推出 Textract Insights，擷取文件欄位並標示出處

**模型與產品**｜來源：[AWS Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/announcing-amazon-textract-insights-verifiable-generative-ai-for-documents/)｜2026-11-21

AWS 宣布 Amazon Textract Insights 正式上線（GA），這是 Textract 新增的生成式 AI 功能。使用者用自然語言描述需要哪些欄位，再上傳單份文件或混合多種文件的文件包，系統會回傳結構化結果，每個欄位值都附上信心分數與所在頁面的依據，而且不需要訓練模型。

> **對企業的意義**：發票、報關單、申請書這類文件的人工建檔作業，可以評估改用這種做法。因為每個欄位都附有信心分數與出處，企業可以設定低於某個分數才轉給人工覆核，在自動化與正確性之間取得平衡。導入前建議先用中文文件實測準確度。

## 3. 第三方供應商遭駭連環爆，國內多家上市櫃公司受影響

**產業動態**｜來源：[iThome](https://www.ithome.com.tw/news/180681)｜2026-11-20

iThome 資安週報指出，全球第三方服務供應商的資安事件持續擴大：愛爾蘭銀行 IT 服務商 Wellington IT 遭駭，約 40 家信用合作社受影響；日本行銷科技業者 PLAID 旗下的 KARTE 平台遭入侵，波及數十家企業。在國內，富邦媒旗下 mo店+、大車隊子公司全球商務科技，以及元太、神達數位、驊陞等企業，也分別發生資料遭未經授權存取或系統遭攻擊的情況。

> **對企業的意義**：導入 AI 客服或知識庫時，等於多了一個能接觸內部資料的外部供應商。建議在合約中寫清楚資料存放位置、存取權限與事故通報時限，只給供應商完成工作所需的最小權限，並定期檢查有哪些外部帳號可以進入系統。

## 4. Gemini API 推出 Tool Retrieval，代理可按需挑工具

**開源與工具**｜來源：[Google AI](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/)｜2026-11-20

Google 在 Gemini API 推出 Tool Retrieval（工具檢索）預覽版，讓 AI 代理可以存取數百種工具，同時減少 token 用量。

> **對企業的意義**：企業要把很多內部 API 或系統功能開放給代理時，如果一次把所有工具說明都塞進提示詞，成本會增加，代理也比較容易選錯工具。這類「需要時才找工具」的機制值得追蹤，但目前仍是預覽版，建議先在非正式環境測試。

## 5. Standard Bank 以 LLM 自動化生成式 AI 風險評估

**企業應用**｜來源：[AWS Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/how-standard-bank-group-automates-ai-risk-assessment-for-generative-ai/)｜2026-11-21

南非 Standard Bank Group 與 AWS 專業服務團隊合作，在自己的 AWS 帳號中建立評估機制，以 Amazon Bedrock 上的 LLM-as-a-judge（由大型語言模型擔任評審）方式，依照國際 AI 標準與銀行內部政策，替每個生成式 AI 使用案例評分，讓風險委員會在核准時有一致、可以追溯的證據。

> **對企業的意義**：AI 使用案例增加之後，人工逐案審查容易標準不一。企業可以先把內部 AI 使用規範整理成檢核清單，讓 AI 協助初步評分、人工做最後決定，並保留評估紀錄。這套做法對受金融或個資法規監管的產業特別有參考價值。

## 6. BMW 分享治理數百個 AI 代理的做法

**企業應用**｜來源：[AWS Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/how-the-bmw-group-governs-hundreds-of-agents-across-thousands-of-developers/)｜2026-11-20

BMW 集團分享旗下研發團隊在企業規模下建置、治理與維運 AI 代理的做法與模式。這些代理有數百個，服務數千名開發人員，目標是在不犧牲速度、品質與法規遵循的前提下運作。BMW 強調，治理不能等到事後才補。

> **對企業的意義**：中小企業的代理數量雖然沒有那麼多，但同樣要從第一個代理開始，記錄它的負責人、可以存取的資料與操作權限。及早建立代理清冊與上線審查流程，之後擴大使用時才不會失控。

## 7. 住友生命靠主管帶頭用，推動 ChatGPT Enterprise 普及

**企業應用**｜來源：[OpenAI](https://openai.com/business/customer-stories/sumitomo-life)｜2026-11-18

日本住友生命使用 ChatGPT Enterprise 研究保險同業、準備提案，並撰寫投資分析用的程式碼。OpenAI 指出，主管早期帶頭使用，是推動全公司採用的關鍵之一。

> **對企業的意義**：台灣企業導入 AI 工具時，常卡在員工不知道怎麼用、也不敢用。可以先請主管在提案準備、資料研究等日常工作中示範使用，並整理部門內的實際使用案例分享出去，效果通常比只辦教育訓練好。

## 8. 微軟與 Salesforce 合作推出 Copilotforce

**產業動態**｜來源：[Microsoft](https://news.microsoft.com/source/2026/11/17/microsoft-and-salesforce-announce-copilotforce-bringing-trusted-customer-context-and-action-into-microsoft-ai-experiences/)｜2026-11-18

微軟與 Salesforce 宣布推出 Copilotforce，目標是把可信任的客戶資料脈絡與操作功能帶進微軟的 AI 體驗中。目前公開資訊有限，具體功能與上線時程仍待官方進一步說明。

> **對企業的意義**：同時使用 Microsoft 365 與 Salesforce 的企業，未來可能可以在 Copilot 裡直接查詢與操作 CRM 資料。建議等細節公布後，先確認授權費用與權限是怎麼對應的，再評估要不要調整現有的客服或業務流程。
