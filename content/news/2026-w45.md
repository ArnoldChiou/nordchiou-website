本週的新聞主軸是 AI 代理正在接進企業系統，配套的治理工作也跟著變重要。OpenAI 先後擴大與 ServiceNow、Oracle 的合作，把代理放進企業本來就在用的系統；AWS 則發表了幾篇實務文章，主題分別是把數百支 API 轉成代理工具，以及管理模型費用。台灣這邊，奇美醫院直接說明 AI 代理還沒上線，原因是安全的執行環境還沒準備好。同一週，PHP2Shell 漏洞被串連利用，受害伺服器包括台灣的機器。內容授權方面，主要 AI 業者將採用同一套訓練退出標準。給企業的建議是：先把資料治理、權限控管、成本歸屬和系統修補做好，再擴大 AI 代理能動手的範圍。

## 1. 四大 AI 業者將採用同一套訓練退出標準

**政策與法規**｜來源：[The Verge](https://www.theverge.com/tech/1023763/openai-google-microsoft-ai-scraping-standard-opt-out)｜2026-10-31

The Verge 報導，OpenAI、Google、Microsoft 與 Anthropic 表示會採用一套新標準，讓網站經營者用共享的「policy token」訊號表達是否同意內容被拿去訓練 AI。網站只要設定一次，就能套用到所有參與的業者，不用逐家分開設定。OpenAI 也在官方部落格表示，會遵循這個透過 robots.txt 傳達的共享訊號。

> **對企業的意義**：有官網、電商頁面或知識文章的企業，可以藉這個機會盤點哪些內容願意讓 AI 拿去訓練、哪些不行，並請網站維護人員關注 robots.txt 的設定方式。要注意的是，擋掉訓練和被 AI 搜尋引用是兩件事，設定前要先分清楚兩者的取捨。

## 2. 奇美醫院：AI 代理上線前先蓋好「龍蝦池」

**企業應用**｜來源：[iThome](https://www.ithome.com.tw/news/180107)｜2026-10-30

奇美醫院院長林宏榮說明院內 AI 發展分四個階段：2005 年起基礎數位化、2019 年成立 AI 中心並從 BI 過渡到 AI、2023 年投入生成式 AI 的「AI 伴行」階段，2025 年起瞄準代理型 AI。伴行階段已推出 A+ HIS Copilot、A+藥安師等助手，協助整理病歷與提醒注意事項。AI 代理目前還沒正式上線，院方表示要先完成資料治理與安全沙盒環境。

> **對企業的意義**：這是很適合台灣企業參考的路線：先用 AI 助手協助員工，累積信任和資料品質，再進入能自動執行任務的代理階段。打算導入 AI 代理的企業，可以先確認資料權限有沒有整理好、有沒有隔離的測試環境，再決定要開放哪些自動化動作。

## 3. 駭客疑借助 AI 串連漏洞，台灣伺服器受害

**產業動態**｜來源：[iThome](https://www.ithome.com.tw/news/180111)｜2026-10-30

以色列資安新創 Dream Security 揭露，使用簡體中文的駭客疑似借助 AI，串連 PHP2Shell 重大漏洞（CVE-2026-109618、CVE-2026-109619）與 Linux 核心權限提升漏洞 Fragnesia（CVE-2026-46300），入侵 25 台伺服器並取得最高權限（root）。受害伺服器分布在台灣、日本、韓國與美國，駭客還藉此深入受害組織內部的 AD 網域環境。

> **對企業的意義**：AI 可能讓攻擊者更快把多個漏洞串成完整的攻擊路徑，從漏洞公開到被利用的時間也跟著縮短。有用 PHP 或 Linux 伺服器、對外提供服務的企業，應該優先確認修補進度。自架的 AI 服務主機同樣要納入修補和權限檢查的範圍。

## 4. OpenAI 擴大與 ServiceNow 合作，代理進流程

**產業動態**｜來源：[OpenAI](https://openai.com/index/openai-servicenow-partnership-expansion)｜2026-10-28

OpenAI 與 ServiceNow 擴大合作，雙向整合：OpenAI 的模型與代理會帶進 ServiceNow，ServiceNow 的工作流程也會帶進 ChatGPT 與 Codex。同一週，OpenAI 也宣布擴大與 Oracle 的合作，把 Oracle 的商業應用程式與 AI 代理帶進 ChatGPT。

> **對企業的意義**：大型平台正讓員工直接在 AI 介面裡操作企業系統。已經在用 ServiceNow、Oracle 等系統的企業，可以留意原廠整合的上線時程，先評估現有授權能不能直接用，再決定要不要另外自建串接，減少重複開發。

## 5. Worldwide Express 用多代理處理貨運帳務異常

**企業應用**｜來源：[AWS Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/how-worldwide-express-automated-freight-exceptions-with-amazon-bedrock/)｜2026-10-31

美國物流業者 Worldwide Express 在 Amazon Bedrock 上打造多代理（multi-agent）系統，自動處理零擔貨運（less-than-truckload）的帳務異常流程。上線六個月後，待處理的異常案件減少 75%，收款週期縮短四週，並釋出 1,000 萬美元的自由現金流。

> **對企業的意義**：這個案例選的是規則多、量大、直接影響現金流的後勤流程，成效容易量化。台灣企業如果有對帳、請款異常、訂單例外這類大量人工判斷的流程，可以先挑一個流程做試點，事先定好要追蹤的指標，例如待處理案件數或收款天數。

## 6. MoEngage 把約 400 支 API 轉成代理工具

**開源與工具**｜來源：[AWS Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/how-moengage-turned-over-400-apis-into-agent-tools-with-agentcore-gateway/)｜2026-10-30

MoEngage 用 Amazon Bedrock AgentCore Gateway，把分布在 7 個 AWS 區域、約 400 支內部 REST API 轉成依權限限制使用範圍的代理工具。做法是根據 OpenAPI 規格產生工具，用 Cedar 政策控管權限，再透過受管的 Amazon VPC Lattice 對外連線。這樣不用為每個服務各建一台 MCP 伺服器，不必開放公開端點，也避免把 400 個工具全部塞進模型的上下文（context，指模型一次能讀取的內容）。

> **對企業的意義**：企業內部系統很多時，讓 AI 代理呼叫 API 最難的通常是權限和規模管理，而不是串接本身。如果系統已經有 OpenAPI 文件，可以集中管理這些工具，並依角色限制代理能呼叫哪些 API，避免代理拿到過大的權限。

## 7. AWS 發布 Bedrock 模型費用管理五階段做法

**開源與工具**｜來源：[AWS Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/managing-amazon-bedrock-costs-end-to-end-a-playbook-for-finops-and-platform-teams/)｜2026-10-31

AWS 針對財務營運（FinOps）與平台工程團隊，提出管理 Amazon Bedrock 費用的五階段做法：把每一筆花費對應到負責人、讓每次請求都可以觀測、強制執行預算、調整平台預設設定，以及定期檢視。

> **對企業的意義**：AI 用量一擴大，費用很容易失控。即使不用 Bedrock，企業也可以參考這套做法：從一開始就依部門或專案標記 AI 用量、設定預算警示，並定期檢視哪些任務可以改用比較便宜的模型。
